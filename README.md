# Auto Farm Recorder (Android)

บันทึกการเล่นเกมของคุณเอง 1 รอบ (แตะ / กดค้าง / ปัด + จังหวะเวลา) แล้วเล่นซ้ำอัตโนมัติ จัดการ Macro ผ่านเว็บ Dashboard ภาษาไทย (Dark Gaming UI)

## 1. ผลการตรวจสอบข้อจำกัดของ Android (ทำก่อนเขียนโค้ด)

| เรื่อง | ข้อสรุป |
|---|---|
| เว็บไซต์ธรรมดาดักการแตะในเกมอื่น / สั่งแตะข้ามแอปได้ไหม | **ไม่ได้** เบราว์เซอร์ไม่มี API เช่นนี้ จึงต้องมีแอป Android แยก (Companion) |
| เล่นซ้ำการแตะข้ามแอป | **ทำได้จริง** ด้วย `AccessibilityService.dispatchGesture()` (ต้องประกาศ `canPerformGestures="true"` และผู้ใช้เปิดบริการเอง) Android 7.0 (API 24) ขึ้นไป |
| บันทึกการแตะข้ามแอป | Android ไม่มี API ให้ "ฟัง" สัมผัสในแอปอื่นตรงๆ วิธีที่ใช้ได้จริงคือ **เลเยอร์โปร่งใสเต็มจอ** (`TYPE_ACCESSIBILITY_OVERLAY`) รับการแตะของคุณ → บันทึก → **ส่งต่อให้เกมทันที** ด้วย `dispatchGesture` |
| Android 13+ ติดตั้งจากไฟล์ APK | เปิด Accessibility ไม่ได้จนกว่าจะ "อนุญาตการตั้งค่าที่ถูกจำกัด" ในข้อมูลแอป (ดูข้อ 4) |

**ข้อจำกัดของวิธีบันทึก (โปรดอ่าน)**
- รองรับ **นิ้วเดียว**: แตะ กดค้าง ปัดเส้นตรง (เก็บแค่จุดเริ่ม–จุดจบ) ไม่รองรับหลายนิ้ว/pinch
- ระหว่างบันทึก เกมจะได้รับการแตะ **หลังยกนิ้ว** (หน่วงเท่าระยะเวลาที่แตะ) เกมที่ต้องควบคุมต่อเนื่องเรียลไทม์ (เช่น ลากจอยสติ๊กค้าง) อาจเล่นไม่ลื่นตอนบันทึก — ใช้ปุ่ม "พัก" เล่นเองแล้วบันทึกเฉพาะช่วงที่ต้องการ
- แอปที่บล็อกบริการ Accessibility (บางแอปธนาคาร/DRM) อาจไม่ตอบสนอง
- เล่นซ้ำต้องใช้หน้าจอ **แนวเดียวกัน** กับตอนบันทึก (ขนาดต่างกันสเกลพิกัดให้อัตโนมัติ แต่ UI ของเกมอาจเลื่อนตำแหน่ง)
- เป็นการเล่นซ้ำตามพิกัดและเวลา **ไม่เห็นภาพบนจอ** — ถ้าเกมมีเหตุการณ์สุ่ม/โหลดช้า Macro อาจคลาดเคลื่อน

> ⚠ **กฎของเกม:** เกมจำนวนมากห้ามใช้ระบบอัตโนมัติ/ออโต้คลิกใน ToS และอาจแบนบัญชี ใช้กับเกมที่อนุญาตหรือเกมออฟไลน์เท่านั้น และรับผิดชอบเอง

## 2. สถาปัตยกรรม

```
┌──────────────── แอป Android Companion (Kotlin) ────────────────┐
│ AutoFarmService (Accessibility Service)                        │
│  ├─ Recorder  : เลเยอร์โปร่งใส + กรอบแดง + แถบควบคุมลอย (พัก/หยุด)  │  ← ส่วนบันทึก
│  ├─ Replayer  : coroutine + dispatchGesture + แถบลอย (พัก/หยุด)  │  ← ส่วนเล่นซ้ำ (แยกกัน)
│  └─ LocalServer: HTTP 127.0.0.1:8765 + โทเค็น + ตรวจ Host/Origin │
│ MainActivity : WebView แสดง Dashboard / หน้าขอสิทธิ์              │
│ TestPadActivity : หน้าทดสอบว่าแตะจริง                            │
└────────────────────────────────────────────────────────────────┘
        ▲ HTTP (เครื่องเดียวกัน)                 ▲ assets
┌───────┴────────── web/ (Dashboard ภาษาไทย) ────────────────────┐
│ macro.js (ตรวจสอบ/นำเข้า-ส่งออก)  db.js (IndexedDB)  api.js      │
│ app.js: แดชบอร์ด · บันทึก · เล่นซ้ำ · คลัง Macro · ตั้งค่า        │
└────────────────────────────────────────────────────────────────┘
```

- Dashboard ถูกแพ็กเป็น assets ในแอปและเสิร์ฟโดย Companion เอง → ไม่ต้องมีเซิร์ฟเวอร์ภายนอก ไม่ต้องใช้อินเทอร์เน็ต
- Macro เก็บใน **IndexedDB** ของ Dashboard (อยู่ต่อหลังปิดเว็บ/รีสตาร์ตเครื่อง); การบันทึกที่ Dashboard ยังไม่ได้ดึงจะค้างในไฟล์ของแอป แล้วถูกนำเข้าอัตโนมัติเมื่อเปิดใหม่
- ความปลอดภัย: bind เฉพาะ loopback, โทเค็นสุ่ม 192 บิต (ส่งผ่าน URL fragment ไม่ถูกส่งไปกับ request), ตรวจ Host/Origin, ไม่มี CORS, CSP เข้มงวด, `allowBackup=false`, ไม่อ่านเนื้อหาหน้าจอ
- รายละเอียด API และรูปแบบไฟล์ JSON: [docs/PROTOCOL.md](docs/PROTOCOL.md)

## 4. ติดตั้ง

### วิธี A — สร้าง APK ด้วย GitHub Actions (ไม่ต้องลง Android Studio)
1. อัปโหลดโฟลเดอร์นี้ขึ้น GitHub repo ของคุณ (branch `main`)
2. แท็บ **Actions → Build APK** (หรือรัน workflow_dispatch) รอจนเสร็จ
3. ดาวน์โหลด artifact `AutoFarmRecorder-debug-apk` → แตกไฟล์ → `app-debug.apk`
4. ส่งไฟล์เข้ามือถือ แล้วติดตั้ง (อนุญาต "ติดตั้งแอปจากแหล่งที่ไม่รู้จัก" สำหรับแอปที่ใช้เปิดไฟล์)

### วิธี B — Android Studio
1. ติดตั้ง Android Studio (JDK 17 มาในตัว) → **Open** โฟลเดอร์ `android/`
2. รอ Gradle sync (ต้องมีเน็ต) → ต่อมือถือเปิด USB debugging → กด Run ▶

### วิธี C — Gradle บนคอมพิวเตอร์
```bash
# ต้องมี JDK 17, Android SDK (ANDROID_HOME) และ Gradle 8.7
gradle -p android assembleDebug
# ได้ไฟล์ android/app/build/outputs/apk/debug/app-debug.apk
```

### เปิดสิทธิ์บนมือถือ
1. เปิดแอป **Auto Farm Recorder** → อ่านคำอธิบายสิทธิ์ → กด "เปิดการตั้งค่าการช่วยเหลือพิเศษ"
2. เลือก **Auto Farm Recorder** → เปิดใช้งาน → ยืนยัน
3. **Android 13+:** ถ้าขึ้น "การตั้งค่าที่ถูกจำกัด" ให้กลับมากด "เปิดข้อมูลแอป" → เมนู ⋮ มุมขวาบน → **อนุญาตการตั้งค่าที่ถูกจำกัด** แล้วทำข้อ 2 ใหม่ (ตัวเลือกนี้อาจโผล่หลังจากพยายามเปิดแล้วถูกบล็อกหนึ่งครั้ง; ชื่อเมนูต่างกันเล็กน้อยตามยี่ห้อ)
4. แนะนำ: ตั้งแบตเตอรี่ของแอปเป็น "ไม่จำกัด" (Samsung/Xiaomi/OPPO อาจฆ่าบริการเบื้องหลัง)
5. กลับเข้าแอป → Dashboard จะเปิดเอง และขึ้น **เชื่อมต่อแล้ว**

## 5. วิธีใช้
1. **บันทึก:** แท็บ *บันทึก* → ตั้งชื่อ → ● เริ่มบันทึก → สลับไปเกม เล่นเอง 1 รอบ (มีกรอบแดงรอบจอ + แถบลอย) → กด **■ บันทึก** บนแถบ (หรือกลับมากด *หยุดและบันทึก*) → Macro เข้าคลังเอง
2. **เล่นซ้ำ:** แท็บ *เล่นซ้ำ* → เลือก Macro, จำนวนรอบ (หรือไม่จำกัด), ความเร็ว, หน่วงก่อนเริ่ม (ไว้สลับไปเกม) → ▶ เริ่ม
3. **หยุด:** ปุ่ม ■ บนแถบลอยในเกม, ปุ่ม 🛑 หยุดฉุกเฉินใน Dashboard, หรือปิดบริการใน การตั้งค่า → การช่วยเหลือพิเศษ (ตัดการทำงานทันที) — ลากแถบลอยไปมุมที่ Macro ไม่แตะ
4. **คลัง:** เปลี่ยนชื่อ แก้ไขพิกัด/เวลา/ชนิด เพิ่ม–ลบขั้น ทำสำเนา ลบ ส่งออก/นำเข้า JSON (สำรองข้อมูลไว้ด้วย)

## 6. ทดสอบ

**อัตโนมัติ (ฝั่งเว็บ):** `npm test` และ `npm run check` — ตรวจ schema/นำเข้า-ส่งออก, IndexedDB/ที่เก็บข้อมูล, ไคลเอนต์ API กับเซิร์ฟเวอร์จำลองตามโปรโตคอล (เซิร์ฟเวอร์จำลองใช้เฉพาะในเทสต์)

**บนมือถือ (พิสูจน์ว่าแตะจริง ไม่ต้องพึ่งเกม):**
1. Dashboard → แท็บ *บันทึก* → ● เริ่มบันทึก → กด **⏸ พัก** บนแถบลอยทันที (ช่วงพักไม่ถูกบันทึก)
2. ไปที่ Dashboard → *ตั้งค่า* → **เปิดหน้าทดสอบการแตะ (Test Pad)** → กด **⏵ ต่อ** บนแถบลอย
3. บน Test Pad: แตะ 3 ครั้ง, กดค้าง 1 ครั้ง (>0.5 วินาที), ปัด 1 ครั้ง (ตัวเลขด้านบนต้องขึ้น 3/1/1) → กด **■ บันทึก**
4. กลับ Dashboard → *เล่นซ้ำ* → ตั้ง "หน่วงก่อนเริ่ม" = 10 วินาที → ▶ เริ่ม → ไป Test Pad แล้วกด **[รีเซ็ต]** ที่มุมขวาบน
5. เมื่อครบหน่วงเวลา ตัวเลขต้องกลับมาเป็น แตะ 3 / กดค้าง 1 / ปัด 1 และจุดปรากฏตำแหน่งเดิม โดยที่คุณไม่ได้แตะหน้าจอเลย = พิสูจน์ว่าสั่งแตะจริง
6. ปิดแอป/รีสตาร์ตเครื่อง → เปิดใหม่ → Macro ยังอยู่ในคลัง
7. ลองวนไม่จำกัดแล้วกดหยุดฉุกเฉิน ต้องหยุดภายในไม่กี่ร้อยมิลลิวินาที

> บันทึกตามจริง: โค้ด Android ในชุดนี้เขียนและตรวจทานแล้ว แต่ **ยังไม่ได้คอมไพล์/รันบนอุปกรณ์จริง** ในสภาพแวดล้อมที่สร้างโปรเจกต์ (ไม่มี Android SDK) — กรุณา build ตามข้อ 4 และทำรายการทดสอบด้านบนก่อนใช้งานจริง หากพบ error แจ้งข้อความมาได้เลย

## 7. แก้ปัญหา

| อาการ | วิธีแก้ |
|---|---|
| เปิด Accessibility ไม่ได้ / ขึ้น "ถูกจำกัด" | ข้อมูลแอป → ⋮ → อนุญาตการตั้งค่าที่ถูกจำกัด (Android 13+) |
| Dashboard ขึ้น "ไม่ได้เชื่อมต่อ" | ตรวจว่าบริการเปิดอยู่; เปิดแดชบอร์ดจากแอป (ไม่ใช่เบราว์เซอร์) หรือวางโทเค็นใน ตั้งค่า; พอร์ต 8765 อาจถูกใช้อยู่ → ปิด/เปิดบริการใหม่ |
| ระบบปิดบริการเอง | ปิดการประหยัดแบตเตอรี่ของแอป; ล็อกแอปไว้ใน recent apps (Xiaomi/OPPO/Vivo) |
| เล่นซ้ำแล้วไม่แตะอะไร | ดูข้อความผิดพลาดใน Dashboard; ตรวจ `ทิศทางหน้าจอ`; เกมบางตัวบล็อกการแตะจาก Accessibility |
| แตะคลาดตำแหน่ง | ใช้แนวจอและความละเอียดเดิม; ปิดโหมดแสดงผล/ขนาดหน้าจอที่เปลี่ยนไป; แก้พิกัดในคลัง → แก้ไข |
| ตอนบันทึก เกมตอบสนองช้า | เป็นข้อจำกัดของวิธีส่งต่อ (ดูข้อ 1); บันทึกเป็นช่วงสั้นๆ โดยใช้ปุ่ม พัก |
| นำเข้า/ส่งออกไฟล์ไม่ได้ | ใช้ปุ่มในแอป (ใช้ตัวเลือกไฟล์ของ Android); เบราว์เซอร์ปกติใช้ดาวน์โหลดไฟล์ได้ตามปกติ |
| ถอนการติดตั้งแล้ว Macro หาย | ข้อมูลอยู่ในแอป — ส่งออก JSON สำรองก่อนถอนเสมอ |

## 8. ความเป็นส่วนตัว
แอปทำงานในเครื่องทั้งหมด ไม่ส่งข้อมูลออกอินเทอร์เน็ต (สิทธิ์ INTERNET ใช้เพื่อเปิดซ็อกเก็ต loopback เท่านั้น และ network security config อนุญาต http เฉพาะ 127.0.0.1) บริการ Accessibility ไม่ขอ `canRetrieveWindowContent` และไม่ฟัง event ของแอปอื่น เก็บเฉพาะพิกัดและเวลาของการแตะที่คุณสั่งบันทึก
